# 📖 ІНСТРУКЦІЯ ДЛЯ ТЕБЕ

## Етап 1.1: Створення таблиці в Supabase

### Крок 1: Відкрий Supabase Dashboard
1. Йди на https://supabase.com/dashboard
2. Вибери свій проект (або створи новий)

### Крок 2: Відкрий SQL Editor
1. В лівому меню натисни **SQL Editor**
2. Натисни **New query**

### Крок 3: Скопіюй і виконай цей SQL:

```sql
-- =============================================
-- ТАБЛИЦЯ ДЛЯ АРХІВУ НОВИН САЙТУ DK NEWS
-- =============================================

-- Видалити якщо існує (для чистого старту)
DROP TABLE IF EXISTS news_archive CASCADE;

-- Створити таблицю
CREATE TABLE news_archive (
    id SERIAL PRIMARY KEY,
    slug VARCHAR(255) UNIQUE NOT NULL,
    title TEXT NOT NULL,
    title_ukrainian TEXT,
    summary_ukrainian TEXT,
    summary_danish TEXT,
    tldr TEXT,
    fun_fact TEXT,
    image_url TEXT,
    source_url TEXT,
    source_name VARCHAR(100),
    category VARCHAR(50) DEFAULT 'News',
    tags TEXT[] DEFAULT '{}',
    mood VARCHAR(20) DEFAULT 'neutral',
    published_at TIMESTAMP WITH TIME ZONE NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    is_archived BOOLEAN DEFAULT FALSE
);

-- Індекси для швидкого пошуку
CREATE INDEX idx_news_published ON news_archive(published_at DESC);
CREATE INDEX idx_news_slug ON news_archive(slug);
CREATE INDEX idx_news_category ON news_archive(category);
CREATE INDEX idx_news_archived ON news_archive(is_archived);

-- RLS (Row Level Security)
ALTER TABLE news_archive ENABLE ROW LEVEL SECURITY;

-- Політика: читати можуть всі
CREATE POLICY "Public read access" 
ON news_archive FOR SELECT 
USING (true);

-- Політика: писати/оновлювати з service_role
CREATE POLICY "Service role write access" 
ON news_archive FOR ALL
USING (true)
WITH CHECK (true);


-- =============================================
-- ГОТОВО! ✅
-- =============================================
```

### Крок 4: Натисни **Run** (або Ctrl+Enter)

Маєш побачити: `Success. No rows returned`

## Етап 1.2: Отримання Credentials

### Крок 1: Знайди API Settings
1. В лівому меню натисни **Project Settings** (⚙️ іконка)
2. Вибери **API** в підменю

### Крок 2: Скопіюй ці значення

| Що копіювати | Де знайти |
|--------------|-----------|
| **Project URL** | Зверху, починається з `https://` |
| **service_role key** | В секції `Project API keys`, натисни `Reveal` біля `service_role` |

⚠️ **service_role key — СЕКРЕТНИЙ!** Не показуй нікому!

---

## Етап 1.3: Додавання Secrets в GitHub

### Крок 1: Відкрий GitHub репозиторій
1. Йди на https://github.com/deusflow/News
2. **Settings** → **Secrets and variables** → **Actions**

### Крок 2: Додай 2 нові secrets

| Name | Value |
|------|-------|
| `SUPABASE_URL` | Твій Project URL (напр. `https://abc123.supabase.co`) |
| `SUPABASE_SERVICE_KEY` | Твій service_role key |

### Крок 3: Перевір
Маєш бачити в списку:
- ✅ `SUPABASE_URL`
- ✅ `SUPABASE_SERVICE_KEY`

## 📊 Логіка роботи системи

### Коли бот запускається (5 раз на день):

```
1. Бот отримує новину з RSS
         │
         ▼
2. Відправляє в Telegram
         │
         ▼
3. Зберігає в Supabase (news_archive)
         │
         ▼
4. Комітить тригер для deploy-site.yml
         │
         ▼
5. Hugo генерує сторінки з Supabase
         │
         ▼
6. Сайт оновлено! 🎉
```

### Структура даних по днях:

```
Сторінка 1 (Сьогодні - 26 січня):
├── Новина 09:00
├── Новина 12:00
├── Новина 15:00
├── Новина 18:00
└── Новина 21:00

Сторінка 2 (Вчора - 25 січня):
├── Новина 09:00
├── ...
└── Новина 21:00

...

Сторінка 10 (16 січня):
└── Новини за цей день

Архів (15 січня і раніше):
└── Всі старі новини (is_archived = true)
```
